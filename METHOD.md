# Методика проверки: расчёт beta по alpha для четырёх красителей

## 0. Паспорт

| Поле | Значение |
|---|---|
| Задача | Рассчитать beta по спектрам alpha четырёх красителей и проверить результат |
| Дисциплина | Физика, оптика |
| Ветка верификатора | Ветка 1: тесты на свойствах; дополнительно сверка с фиксированным численным эталоном |
| Дата записи методики | 2026-11-07; разделы 0–7 фиксируются отдельным коммитом до первого прогона решения агентом |
| Метка git | Планируемая — `exp-verifier`; в комплекте ещё не создана |

## 1. Замысел

- **Вопрос:** воспроизводит ли реализация агента расчёт молярного инкремента
  действительной части показателя преломления beta по заданной alpha через
  соотношение Крамерса—Кронига?
- **Гипотеза:** при одинаковых входах и дискретизации результат совпадёт с эталоном;
  нулевая alpha даст нулевую beta, а удвоение alpha удвоит beta.
- **Что считается ответом:** четыре спектра beta, вердикт проверки контрольных
  точек и свойств, а также вывод проверки на ошибочной и исправной реализации.

## 2. Постановка

| Что | Значение |
|---|---|
| Что меняем (факторы и уровни) | Краситель: тартразин, индигокармин, метиленовый синий, флуоресцеин. Для проверок свойств: исходная, нулевая и удвоенная alpha |
| Что фиксируем | Входные сетки и alpha, диапазоны интегрирования, дискретную формулу и допуски |
| Что измеряем, в каких единицах | beta и абсолютную ошибку относительно эталона в M⁻¹; прохождение проверок свойств |
| Базовая линия | Контрольные значения `checks/beta_reference.csv` |

При молярной концентрации c величины связаны с показателем преломления:
`n'' = n''_solvent + alpha*c`, `n' = n'_solvent + beta*c`.
Здесь вычисляется только beta, без добавления растворителя и умножения на c.

Фиксированная дискретная формула:

```text
h = wavelength_nm[1] - wavelength_nm[0]
beta[j] = (2/pi) * h * sum по всем k != j:
    alpha[k] / (wavelength_nm[k] * (1 - (wavelength_nm[k]/wavelength_nm[j])**2))
```

Диагональный член исключается. У остальных узлов, включая края, полный вес h.
Сглаживание, изменение выданной сетки, достраивание хвостов и поправки не применяются.

Коды в таблице — обозначения нарушений в методике. Скрипт сообщает ошибки текстом.
Перед импортом решения проверяются хэши всех входов и эталона, схема, число строк,
диапазоны, равномерность и конечность. Любое изменение версии останавливает проверку;
эталон должен содержать ровно шесть именованных контрольных строк на краситель.

**Известные особенности.** Сетка индигокармина первоначально имела шаги 0,50–0,51 нм.
Перед выдачей выполнена линейная интерполяция на равномерную сетку с теми же границами
и числом точек, без экстраполяции. Остальные alpha перенесены без изменения значений.
У тартразина сохранена 31 отрицательная точка alpha, у метиленового синего — 6.
Эти значения не обнуляются. Эталон beta пересчитан для выданных alpha;
старые pickle-кэши, измеренная beta и нерезонансные поправки не используются.

## 4. Код и окружение

- **Где код:** `src/solution.py`. Чистая функция
  `kk_beta(wavelength_nm, alpha_M_inv)` принимает одномерные массивы одинаковой
  длины на положительной равномерной возрастающей сетке (не менее двух узлов)
  и возвращает действительный конечный numpy-массив beta той же формы.
  Alpha может иметь любой знак. Импорт модуля не запускает расчёт и не пишет файлы.
- **Команда запуска из корня:** `python src/solution.py`.
  Входы — `stain_data/*_alpha.csv`, выходы — `results/*_beta.csv`.
  Пути определяются относительно проекта. Эталон не читается решением.
- **Дополнительный режим:** `python src/solution.py --benchmark` выполняет замеры
  раздела 8. Перебор и журналирование выполняются кодом, без отдельных вызовов
  агента на каждый краситель.
- **Окружение:** `source .venv/bin/activate`; проверено наличие Python 3.14.5
  и NumPy 2.5.3. Новые пакеты не требуются. Эталон подготовлен на Python 3.14.5,
  NumPy 2.5.2; точные версии фактического запуска записываются в `diary.md`.
- **Значения seed:** не используются, расчёт детерминированный.

## 5. Верификатор

- **Что проверяет:** версию и договор о данных, комплектность эталона,
  значения beta в контрольных узлах, форму и конечность всех ответов функции,
  нулевой вход, удвоение alpha, аддитивность на синтетических входах
  и соответствие сохранённых CSV результату функции.
- **Полная команда из корня:** `python checks/verify.py`,
  после `python src/solution.py`. Только полный режим с кодом 0 и строкой
  `ПРОЙДЕНО` означает принятие вычислительного результата.
- **Проверка подготовки без решения:** `python checks/verify.py --inputs-only`.
  Короткая проверка функции без выходных CSV: `python checks/verify.py --smoke`.
  Эти режимы не заменяют итоговую проверку.
- **Где лежит:** `checks/verify.py`, эталон — `checks/beta_reference.csv`.
  Верификатор только читает файлы. Агенту запрещено менять `checks/`,
  `stain_data/`, допуски и права доступа к ним.
  До запуска владелец среды закрывает оба каталога от записи
  (`chmod -R a-w checks stain_data` либо ограничениями среды).
- **Чего не проверяет:** точность непрерывного интеграла на бесконечном диапазоне,
  порядок сходимости, качество исходных измерений и предсказание рассеяния в ткани.
  Это ветка свойств, а не исследование сходимости численной схемы.
- **Самопроверка курса:** `check_week6.py --run` может выбрать первым старый
  `checks/check_review.py`. Его зелёный результат не заменяет прямую команду
  новой проверки beta, указанную выше.

На каждый краситель приходится шесть контрольных строк: глобальные минимум и максимум
beta, точка максимума alpha и ближайшие узлы к 500, 700, 800 нм. Сравниваются значения
по сохранённым индексам узлов. У флуоресцеина пик alpha совпадает с узлом 500 нм,
поэтому две строки относятся к одной точке.

| Свойство | Почему должно выполняться | Тест |
|---|---|---|
| Совпадение с эталоном | Одинаковые входы и дискретная формула должны воспроизводить результат | Сравнение 24 контрольных строк |
| Нулевая alpha даёт нулевую beta | Все слагаемые суммы равны нулю | `kk_beta(x, 0) ≈ 0` |
| Удвоение alpha удваивает beta | Формула линейна по alpha | `kk_beta(x, 2*alpha) ≈ 2*kk_beta(x, alpha)` |
| Аддитивность | Формула линейна по alpha | `kk_beta(x, a+b) ≈ kk_beta(x, a)+kk_beta(x, b)` на сетках 7, 17, 31 узел |
| Размер и конечность beta | На каждый входной узел должно приходиться одно конечное действительное значение | Проверка массива результата |
| Сохранённый спектр соответствует функции | CSV должен содержать рассчитанную beta на исходной сетке | Сравнение четырёх выходных файлов с результатами функции |

## 7. Правило принятия (записано до запуска)

1. **Метрика и единицы:** абсолютная ошибка `abs(beta-beta_ref)` в M⁻¹
   в каждой контрольной точке. Должны пройти все точки.
2. **Повторы:** 4 повтора на различных детерминированных конфигурациях — четырёх красителях.
   Для каждой дополнительно проверяются нулевая и удвоенная alpha.
   Отдельно проверяется аддитивность на трёх синтетических сетках.
   Повторы одинакового расчёта с разными seed не нужны.
3. **Сравнение:** поточечное сравнение с фиксированным эталоном. Доверительные
   интервалы, p-значения и поправки не применяются: проверяются детерминированные
   вычисления, а не статистическое различие вариантов.
4. **Практический порог:** `abs(beta-beta_ref) <= 1e-9 + 1e-7*abs(beta_ref)`.
   Это требование воспроизведения фиксированной численной суммы: относительная
   точность 10⁻⁷ с абсолютным запасом 10⁻⁹ M⁻¹ около нуля; не погрешность прибора.
   Допуск фиксирован до прогонов и не оценивается по ошибке решения агента.
   Для нулевого входа — `atol=1e-12`, `rtol=0`; для удвоения и аддитивности —
   `atol=1e-11`, `rtol=1e-9`.
5. **Выбор варианта:** принимается реализация, прошедшая весь набор проверок
   для всех красителей. Малая средняя ошибка не компенсирует провал отдельной точки.
6. **Разбиение для вывода:** все четыре выданных спектра и проверенные преобразования
   входа. Обучающего разбиения нет.
7. **Остановка:** при первой ошибке верификатор завершает работу с кодом 1.
   Исправляется решение; входы, эталон и допуски не меняются. Готовность —
   `ПРОЙДЕНО`, код 0, и сохранённая демонстрация отказа на внесённой ошибке.
